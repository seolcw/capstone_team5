## 1. 구조

```
질문 → [입력 검사 guard (작업 1, 있으면)]
     → [LLM 의도 분류 · JSON]
     → [코드 ★오분류 방지]
          ① 허용된 의도만   ② 키워드 근거 없음 + 다른 유형을 가리킴 → agent
          ③ 처리기 전제 조건(대상 주문·클레임·쿠폰) 불충족 → agent   ④ 분명한 근거가 있는데 빠진 의도 보충
     ├ 취소·반품·교환 판정 ─── v2 rules (+ 사용·착용·개봉 고지 시 상품별 불가 사유 대조)
     ├ 배송조회·지연·보상 ─── 택배사 데이터 기준, 요일 포함 날짜, 지역(제주·도서산간), 지연 보상(CPN-004)
     ├ 배송사고 ───────────── E07 상담원 이관 + 주말 콜백
     ├ 환불·교환 진행 ─────── claim(환불액·차감·입금 예정일·교환 옵션·1회 제한)
     ├ 배송지 변경 ─────────── 주문 상태 기준(SHIP-008)
     ├ 쿠폰·적립금·등급 ───── 쿠폰 복원(CPN-010)·보유 쿠폰·적립금 소멸·등급 혜택(TOS-005)
     ├ 상담원 연결·안전사고 ── E10 콜백 / E02 당직 즉시 연결
     ├ 정책 문의 ───────────── 승인·시행 중·공개 문서만 + 제목 가중 검색 → LLM 1회 (저비용 RAG)
     └ 그 외 · 오분류 의심 ─── v1+ agent (도구 결과 검증 버전)
     → [LLM 문장화] → [코드 출력 검증: 필수 사실 · 금지 표현 · 중국어 혼입 → 실패 시 코드 초안 사용]
```

## 2. 오분류 방지 동작 확인 (분류기가 틀렸다고 가정한 시험)

| 질문 | 일부러 틀린 분류 | v3 동작 | 근거 로그 |
|---|---|---|---|
| 키보드 아직 배송중이에요? | 쿠폰문의 | **agent 로 이탈 방지** | 분류 근거 없음, 질문 근거 '배송' |
| 환불해줘 | 상담원연결 | **agent 로 이탈 방지** | 질문 근거 '반품·클레임' |
| 무료배송 얼마 이상이에요? | 범위외 | **agent 로 이탈 방지** | 범위외인데 쇼핑 키워드 있음 |
| 제 쿠폰 몇 장 있어요? | 배송조회 | **agent 로 이탈 방지** | 질문 근거 '혜택' |
| ??? | (없음) | **agent 로** | 분류 결과 없음 |
| 내일 날씨 어때요? | 범위외 | 범위외 응답 (정상) | — |

→ 분류가 틀려도 **엉뚱한 코드 경로로 가지 않고**, 비싸지만 범용인 v1+ agent 로 넘어감. (이번 평가 126회에서는 실제 이탈이 0회라 agent 경로가 쓰이지 않음)

## 4. 과적합 점검 — 정직하게
- 코드에 **케이스 ID·고객 ID·정답 문장 없음**. 모든 사실은 주문·배송·쿠폰·고객 데이터와 승인된 정책 문서에서 계산.
- 공개셋에 없는 고객(C0027~C0047) · 다른 표현으로 만든 **자체 검증 12개**에서도 통과 → 공개셋 암기가 아님을 보여주는 근거.
- **단, 한계**: 자체 검증 세트의 실패 4건을 보고 규칙을 고쳤으므로, 이 세트는 이제 '완전히 새로운' 시험은 아님. 비공개 평가셋(멘토 측정)에서는 새로운 표현·유형이 나올 수 있음.
  → 처리기가 없거나 의심스러운 질문은 v1+ agent 로 가도록 설계해 **틀린 확답 대신 범용 처리**로 떨어지게 함.
- 키워드 규칙은 **표현을 바꾸면 놓칠 수 있음** (예: '뿌려봤는데' 대신 '한 번 써봤어요'는 잡지만 '테스트해봤어요'는 못 잡음).
