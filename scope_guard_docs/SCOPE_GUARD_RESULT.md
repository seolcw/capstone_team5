- 관문 판단은 **3회 모두 같았습니다** (유사도는 계산이 고정, 분류는 temperature 0).
- **타사 이름 규칙이 효과를 냈습니다.** "11번가는 무료배송 기준이 얼마예요?"는 유사도 0.661 로 통과 기준(0.65)을 넘었지만, 타사 이름 때문에 ③ 으로 보내져 차단됐습니다.
- 범위 밖 질문의 절반 가까이(27/60)는 LLM 호출 없이 유사도만으로 끝났습니다.

## 6. 추가 검증

### 6-1. 공개 평가셋 30개 — 오차단 확인 (`guard_only.py`)

공개 평가셋은 전부 실제 고객 문의라, 관문이 하나라도 막으면 오차단입니다. 공개 평가셋은 유사도 기준 문장에 넣지 않았으므로 관문이 처음 보는 질문입니다.

| 결과 | 수 |
|---|---|
| 통과 (막히지 않음) | **30 / 30** |
| ② 유사도 높음으로 바로 통과 | 20 |
| ③ LLM 분류가 범위 안으로 판단해 통과 | 10 |
| 긴급 규칙 오작동 | 0 |

### 6-2. 유사도 기준점 흔들림 (`threshold_sweep.py`)

질문 60개(30문항 + 공개 평가셋 30)의 유사도·분류를 한 번씩 구하고, 기준점 9개 조합으로 처리 결과를 계산했습니다.

| 낮은 기준점 | 높은 기준점 | 범위 밖 차단 | 오차단 | 긴급 연결 | LLM 분류 호출 | 틀린 질문 |
|---|---|---|---|---|---|---|
| **0.40** | 0.60 | 20/20 | 0/39 | 1/1 | 20/60 | - |
| **0.40** | **0.65** ← 변경 후 | 20/20 | 0/39 | 1/1 | 24/60 | - |
| **0.40** | 0.70 | 20/20 | 0/39 | 1/1 | 30/60 | - |
| 0.45 | 0.60 | 20/20 | 0/39 | 1/1 | 20/60 | - |
| 0.45 | 0.65 ← 주 시험 | 20/20 | 0/39 | 1/1 | 24/60 | - |
| 0.45 | 0.70 | 20/20 | 0/39 | 1/1 | 30/60 | - |
| 0.50 | 0.60 | 20/20 | **4/39** | 1/1 | 11/60 | PUB-004, 007, 008, 009 |
| 0.50 | 0.65 | 20/20 | **4/39** | 1/1 | 15/60 | PUB-004, 007, 008, 009 |
| 0.50 | 0.70 | 20/20 | **4/39** | 1/1 | 21/60 | PUB-004, 007, 008, 009 |

**읽는 법**
- **높은 기준점은 정확도에 영향이 없고 비용만 바꿉니다** (LLM 분류 20 → 24 → 30회). 정확도가 아니라 비용·속도를 조절하는 값입니다.
- **낮은 기준점을 0.50 으로 올리면 실제 고객 문의 4개가 막힙니다.**

| 막힌 질문 (0.50 일 때) | 유사도 |
|---|---|
| 청바지 핏이 별로라 반품하고 싶어요 (PUB-007) | 0.492 |
| 한우 받았는데 생각보다 별로네요. 반품할게요 (PUB-009) | 0.488 |
| 모니터 주문한 지 일주일 넘었는데 왜 안 와요? (PUB-004) | 0.471 |
| 블루투스 스피커 써봤는데 그냥 환불하고 싶어요 (PUB-008) | 0.460 |

상품 이름이 구체적이고 감정이 섞인 실제 고객 말투는 FAQ 의 정형화된 문장과 덜 닮게 나옵니다.
0.40~0.55 구간에는 범위 밖(최고 0.544 KTX)과 범위 안(최저 0.460 스피커 환불)이 섞여 있어, 이 구간은 유사도만으로 가를 수 없고 ③ LLM 분류가 반드시 필요합니다.

**기준점 변경 — 0.45 → 0.40**
주 시험의 0.45 는 가장 낮은 실제 고객 문의(0.460)와 간격이 **0.01** 뿐이었습니다. 0.40 은 위 표에서 차단·오차단·긴급·LLM 호출 수가 0.45 와 모두 같고, 간격은 **0.06** 으로 넓어집니다.
점수를 올리려는 변경이 아니라 **같은 성적에서 오차단 위험을 줄이는 쪽**을 택한 것이며, 시험 결과를 보고 바꾼 것임을 밝혀 둡니다. 0.40~0.45 사이에 든 질문이 없어 30문항·공개 평가셋 처리 결과는 변경 전과 같습니다.

## 7. 한계 (정직하게)

- **시험지가 작고 설계한 사람이 만들었습니다.** 범위 밖 20 · 긴급 1 은 적고, 관문을 아는 사람이 쓴 질문이라 쉬웠을 수 있습니다. → 관문을 모르는 팀원이 쓴 질문, 비공개 평가셋·보안 테스트셋으로 다시 확인할 예정입니다.
- **유사도만으로는 범위 안·밖이 갈리지 않습니다** (6-2절). ③ LLM 분류가 범위 밖 차단의 절반 이상(33/60)을 맡고 있어, 분류 프롬프트가 흔들리면 성적도 흔들릴 수 있습니다.
- **기준점 0.40 은 시험 결과를 보고 정했습니다.** 같은 시험지로 다시 재면 유리하게 나올 수 있으므로, 새 시험지로 확인이 필요합니다.
- **3회 반복이 거의 같은 결과를 냈습니다** (temperature 0). 반복은 "흔들리지 않는다"는 근거는 되지만, 표현을 바꾼 질문에 대한 강건함까지 보여 주지는 않습니다.
- **관문은 범위 안 답변의 품질은 고치지 않습니다.** 아래는 v1 자체의 문제로, 다른 담당과 공유가 필요합니다.

| v1 자체 문제 (범위 안 질문) | 해당 |
|---|---|
| 주문 목록을 조회할 수 있는데 주문번호를 되물음 | SC-21, 25, 27 |
| 존재하지 않는 주문번호 "123456"을 지어냄 | SC-28 (2·3회차) |
| 간단한 등급 문의를 없는 코드 gc_01 로 이관 | SC-24 |
| 상담원 요청을 E10 대신 E01 로 이관, 토요일인데 "곧 연결" | SC-30 |
| 쿠폰 조회 도구가 없어 마이페이지 안내 | SC-23 |
