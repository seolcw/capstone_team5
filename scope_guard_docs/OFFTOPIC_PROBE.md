## 다음 단계 — 입력 문지기

질문이 에이전트로 들어가기 전에 갈래를 나눕니다.

| 판단 | 처리 | 판단 주체 |
|---|---|---|
| 긴급 (부상·화재·소송·계정 도용) | 즉시 상담원 연결 (E01·E02·E08), 주말에도 당직 | 코드 규칙 — 놓치면 안 되므로 LLM 에 맡기지 않음 |
| 범위 밖 | 정해진 안내 문구, 모델·도구 호출 없음 | LLM 분류(JSON) + 코드 허용값 검증 |
| 인사·감사 | 짧은 정해진 답 | LLM 분류 |
| 섞인 질문 | 범위 안 부분만 에이전트로 | LLM 분류 |
| 범위 안 · 판단 애매 | 그대로 에이전트로 (오차단 방지) | 코드 기본값 |

목표 (같은 30문항으로 재측정):
- 범위 밖 차단 9/20 → 18/20 이상, 특히 작업 요청·타사·조작
- 범위 안 오차단 0 유지 + 공개 평가셋 30개도 하나도 막히지 않을 것
- SC-26 안전사고 E02 당직 즉시 연결
- 막은 질문은 LLM·도구 호출 0 → 범위 밖 질문당 약 760 토큰 절약

개인 저장소에서 시제품을 만든 뒤 v2 의도 분류 앞에 붙이는 방향으로 브랜치를 따서 올릴 예정입니다. v2 파일을 고치기 전에 팀과 먼저 맞추겠습니다.
